## 2. 最终运行结构

```text
新 stack 配置 + 新启动入口
    ├─ rin-memory 服务（唯一 MemoryCore、根锁与维护循环）
    │    ├─ /v1：对话、上下文、事件、管理、消费回执
    │    └─ /：现有水彩 WebUI，与 API 同源
    └─ N.E.K.O 宿主
         ├─ HTTP 记忆客户端、待同步队列
         ├─ 对话模型、会话、主动交流、插件/游戏调度
         └─ TTS、实时语音、Live2D、表情、动作与打断
```

宿主保留需要的进程和路由，但记忆路由只做协议转发。管理台直接由服务托管，不再启动另一个装配 `MemoryCore` 的 WebUI 进程。核心维护只在服务进程运行。

人格正文、事实、反思、成长、删除屏障和发布版本由服务保存；宿主保留本轮生成所需的有版本快照及待上传记录。宿主本地缓存不承担人格编辑或记忆权威存储。

### 2.1 新配置与新目录

以下布局已由新入口建立，运行目录位于源码仓库之外；host 目录的宿主状态与待同步队列在 A/C 后续接线中启用：

```text
F:\game\projectNEKO\companion-runtime\
    config\stack.toml        # 唯一运行配置入口
    memory\                  # 服务自己的新记忆根
    host\                    # 宿主自己的新状态、会话与待同步队列
    logs\                    # 服务、宿主及启动器日志
    state\                   # 本次启动的进程、端口与实例标识
```

`stack.toml` 通过标准库 TOML 解析，明确以下配置：

| 配置组 | 内容与规则 |
|---|---|
| 路径与实例 | 配置 schema 版本、memory/host/log/state 根；相对路径统一相对配置文件解析 |
| 服务 | 监听地址、端口、上下文期限、提交期限、模型并发、队列容量、退出期限；首版回环监听 |
| 角色 | 稳定 character_id、显示名、默认主体；初始人格正文通过管理台新建 |
| 模型 | 服务提炼/演化与 `/chat` 档位；TOML 可引用凭据环境变量名，管理台也可写入新 state 根的本机配置，立即生效并重启保持；宿主档位后续接线 |
| 宿主 | 源码或安装位置、Python/启动目标、各进程端口、服务 URL、客户端身份；不再读取旧记忆引擎开关 |
| 表现与插件 | 语音、模型资源路径、Live2D、启用插件及插件配置目录；资源可复用，运行设置从新配置产生 |
| 演化 | 默认 off，通过管理台显式选择 propose/auto，持久状态仍由服务管理 |

初始化生成可编辑的模板并列出缺项；启动时校验路径、端口、模型档位、凭据引用与资源路径。配置缺项直接指向新配置中的字段，不搜索旧配置补值。新运行路径的宿主与插件数据根必须显式传入，防止未配置的组件落回旧锚点或旧私有目录。

### 2.2 新启动入口

`rin-memory/tools/stack.ps1` 已提供 `init/start/stop/status` 四个动作及帮助示例。当前已接通服务和同源管理台，宿主与桌宠启动在 A/C 后续补齐。使用形式为：

```powershell
.\tools\stack.ps1 init -Config F:\game\projectNEKO\companion-runtime\config\stack.toml
.\tools\stack.ps1 start -Config F:\game\projectNEKO\companion-runtime\config\stack.toml
.\tools\stack.ps1 status -Config F:\game\projectNEKO\companion-runtime\config\stack.toml
.\tools\stack.ps1 stop -Config F:\game\projectNEKO\companion-runtime\config\stack.toml
```

- `init`：已实现生成新模板与目录；重复执行保留已有新配置及数据，输出下一步需要填写的字段。
- `start`：已实现校验配置 → 启动服务 → 等待 storage/管理能力就绪 → 打开管理台。人格/模型未就绪时仍可进入初始化页面，对话入口显示具体缺项；待补启动宿主和桌宠。
- `stop`：已实现服务停止接收、排空任务、停止维护、释放根锁并记录退出结果；待补宿主停止新轮次、保存待同步状态与关闭宿主。
- `status`：已显示服务实例、进程、端口、实际配置路径、角色、各项能力与服务积压；待补宿主各进程及待同步队列状态。

重复启动不得拉起第二份实例；端口被无关进程占用时明确报冲突。启动中途失败只收拢本次启动的进程；服务意外退出时宿主显示断开状态，不自动启动本地核心。后台进程隐藏窗口启动。
