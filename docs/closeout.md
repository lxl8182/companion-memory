**1. 目标与顺序**

把已有独立核心接成日常可用的系统：记忆与当前人设有唯一权威来源，原 NEKO 文字、语音、情绪、Live2D 与游戏行为保持连续；用户能在管理台理解、修改和撤回变化，开启自动模式后能由真实经历形成局部人设变化。

现有交付覆盖核心记忆流程、人设卡/发布/提案/审核接口和临时目录迁移演练。收尾补齐宿主调用、后台演化、管理界面和真实使用验收。B08—B14 的历史测试记录保留，按原执行卡逐项补齐剩余内容。

顺序：C01 → C02 → C03 → C04 联调 → C05 → C06。管理台页面、视觉和合成数据交互可提前开发；C01 确定接口归属后接真实服务。C01—C05 的源码与隔离验证可独立于正式部署推进；现有运行根与 `nekodata` 可直接读写、清空、重来，人格卡不重建。

> 本文件是历史收尾记录。2026-10-25 起本轮的运行规则以根 `AGENTS.md` §9 为准：数据可清空重来、运行开关按需调整，唯一例外是人格卡不重建。

**2. 六项收尾任务**

**C01｜统一宿主读写和生命周期（补 B08）**

主要位置：宿主 `app/memory_server/engine_bridge/`、现有 routes/post_turn/runtime 与维护任务。复用核心已有服务。

- 把 B01 路由清单逐项标成“委托核心 / 宿主保留 / 明确停用”，覆盖文本更正、无显式 ID 删除、`get_persona/get_settings/new_dialog`、其余 companion events，以及导入/导出。保持原 wire 字段、错误、ID 和送达语义。
- 对原维护循环、抽取、角色配置同步和后台写任务逐一明确所有者。新引擎启用后由同一权威组件处理其数据；失败保留可重试回执，避免请求转入旧写路径形成第二个写入者。
- 补齐角色创建/切换/重命名/删除、release/reload、数据根变化与写入许可；旧 generation 的任务和客户端不得写回新角色。
- 管理台经宿主 API 转交给同一引擎。独立运行模式也只由一个进程持有数据根；打开管理页面时不自行创建第二份引擎或直接改 JSON。

验收：在临时根启用真实核心与适配器，模型可用固定替身。完成聊天记录→抽取→查询→更正→删除→重启；重试只生效一次；角色切换阻止旧任务回写。记录实际读写入口和被替换的旧任务。

交付：完整路由归属、单写者生命周期接线、供 C04 使用的 API 字段与错误示例，以及关闭引擎时原路径的回归结果。

**C02｜让当前人设被所有生成入口采用（补 B10/B11）**

- 初次导入后核心卡成为权威，`characters.json` 保存兼容投影；`ensure_persona` 等旧同步不再覆盖已演化卡。旧编辑入口和直接改文件的用户修改应识别为有基版本的显式编辑；冲突交给用户选择，保留未保存内容。
- 人设语义与工具/语音/表现协议分开组装。普通聊天、主动交流、游戏使用同源快照；游戏人格文本与版本成对更新，旧 planner 结果按版本重新评估。
- 实时模式按客户端能力，在响应结束后更新并等待确认，或准备新连接后交接。输入、播放、打断和控制权延续宿主现有实现。
- 区分已保存、待发布、已发布、各消费者已采用。失败只重试未完成步骤；删除/更正到来时失效旧投影、缓存与待发布快照。

验收：修改一个开放段落，检查下一次文本、主动生成、当前启用实时模式和游戏请求实际携带的版本与内容。覆盖更新中继续输入/打断、基版本冲突、旧配置同步、来源删除后重启。

交付：投影与编辑接线、各消费者更新及确认机制、管理台可读取的生效状态。保留声音、Live2D 资源及控制协议。

**C03｜补齐后台自动演化闭环（补 B12/B13）**

已有 `evolve_persona`、审核与改卡接口；按以下目标合同接入现有 maintenance/outbox，复用持久回执，不增加第二个后台服务。

| 模式 | 后台行为 | 卡片变化 |
|---|---|---|
| 关闭（默认） | 不新建自动演化任务；保留历史与当前卡 | 用户仍可手工编辑 |
| 仅提案 | 满足独立证据与预算条件后生成提案 | 等用户接受后修订、发布 |
| 自动演化 | 在用户开放段落内生成、审核并接受合格提案 | 自动修订并发布，不合格项保留原因 |

- 将现有开关迁移到明确模式：旧 `false` 保持关闭，旧 `true` 保留“仅提案”语义；启用自动改卡由用户明确选择。一个持久设置源驱动调度、核心检查与 UI，消除多个开关互不生效的情况。
- 触发依据是新成立的独立经历/成长；同一证据集合、目标段落和基版本幂等。AI 复述、镜像、时间流逝、沉默不增加依据；游戏战术与主体范围延续现有规则。
- 模型生成结构化提案；检查证据是否足够、修改是否受依据支持、是否越过冻结/范围/字段边界。自动模式通过审核后复用 `accept → revise → publish`。来源删除、用户手改和版本变化发生竞争时，重新检查后再提交。
- 预算、冷却、任务合并、超时和重试使用现有配置与任务设施。新增模型调用全部在后台；无变化、预算不足、待审核、失败可重试有明确结果。
- 提案已接受但发布失败时恢复发布；关闭模式或冻结段落会拦截尚未提交的自动任务。已吸收到卡片的成长不再次重复注入人格块。

验收：完成独立经历→成长→后台触发→合格提案→自动改卡→C02 消费者采用；覆盖重复触发、重启续跑、关闭/冻结、模型无效输出、手改冲突与来源删除。按独立风险补必要测试，复用既有用例。

交付：三种模式、后台触发与恢复链、可追溯的一次完整演化。默认设置维持关闭。

**C04｜WebUI 管理台与真实操作闭环（补 B13）**

复用用户正在开发的 `webui/`。先核对当时工作树及接口，保持已有技术栈和视觉探索，再按下节合同联调。页面经宿主 API 使用同一核心，独立管理入口沿用已有服务能力。

当前交付（2026-10-23）：用户正在做 `webui/` 美术与正式页面，**现有前端文件未改动**；为不阻塞验收，另建独立测试前端 `webui/testbed/`（原生 HTML/CSS/JS，无构建/外部依赖）与 `webui/tests/test_testbed_api.py`（6 tests），并在 `webui/server.py` 做加法 API（engine/status、evolution mode、persona consumers/adopt/sync、cleanup/delete、evolution evaluate/retry、/testbed 静态路由；旧响应字段保留）。测试前端已走通：看来源→改卡→发布→消费者 adopt→提案接受/撤回→删除来源→搜索/导出→重启保持（`.scratch/check_c04_webui.py` exit 0）。

最终联调约定：等用户 `webui/` 完成后，把测试前端验证过的同一组 API 调用迁入正式页面（或保留 testbed 作为调试台），按 §3 合同逐页接真实数据；正式页面只需消费 C01—C03 已固定的 API，不再改核心/宿主协议。联调验收在 C06 一起做，重点见 §6。

- 页面开发可使用明确标注的合成数据，接通后展示实际连接、数据源和角色；连接失败展示真实状态与重试操作。
- 提交带角色/主体/场景与基版本；有副作用的重试复用请求 ID。角色切换取消或忽略旧响应，列表与详情不串角色；编辑冲突保留草稿。
- 修改、冻结、接受/拒绝、模式切换、撤回和删除消费核心回执；显示 pending/failed/retry 以及消费者采用进度。删除说明清理范围；撤回修订与删除原始经历为独立操作。
- API 延续宿主鉴权、同源和错误处理；浏览器不获得模型密钥，不自行决定可演化字段与来源可信度。

验收：在临时根用界面完成看来源→改卡→看到采用状态→接受提案→撤回→删除来源→刷新及重启；覆盖空数据、加载失败、重复点击、并发编辑、窄窗口与键盘操作。

交付：真实 API 联调的管理台、各状态与操作结果；页面和视觉建议见 §3/§4。

**C05｜新引擎开启时的集成、性能和迁移演练（补 B09/B14）**

- 组合真实核心、宿主适配器、后台任务和 WebUI，在隔离环境运行。分别记录默认关闭旧链路、启用新引擎、实机三组结果。原 100 项核心、25 项适配器、506 项宿主回归和 71 项前端结果作为历史基线。
- 按 A01—A16 记录场景、配置、结果和缺项，串起记忆、人格、管理台与表现层。优先复用测试；现有并发语言用例失败保留基线归属，若影响必要链路则在本轮解决。
- 记录 `turn_context/recall` 耗时、超时比例、首字/首音和前台模型调用数；在相同数据规模、模式与模型条件下对比。沿用现有等待预算；先明确比较口径及可接受目标，再据测量决定修正。
- 固定核心 wheel、宿主适配器与 WebUI 对应版本/哈希；保留既有未提交改动，形成可恢复的发布基线。
- 在一致性副本演练停写→备份校验→恢复屏障→迁移→单写者启动→产生新记录→回滚。检查新增对话/更正/删除仍在、旧宿主能读当前人设投影，重启不复活旧内容。迁移钩子的源码接线在本项完成。

验收：A01—A16 各项有对应核心/集成/实机证据归属；演练经过真实适配器与 UI；发布包可重装，回滚步骤可复现。实机与正式数据操作按当次授权执行，未完成的实机项进入 C06 清单。

交付：结果回填 roadmap，引用稳定的测试入口与必要运行记录；关键执行说明收进版本控制文档，`.scratch/` 作为历史过程材料。

**C06｜正式切换和当前角色实机验收（B15）**

前置：C01—C05 完成；依据已有授权核对当次目标角色、数据根、服务状态、切换时机和恢复入口。停止范围只覆盖实际需要的服务。

顺序：停写并备份 → 安装固定版本并迁移 → 切换唯一写入者 → 恢复原启动方式 → 自动演化关闭时检查原体验 → 用户选择演化模式与段落 → 验证一次演化及撤回/删除 → 记录交付版本。

当前角色至少完成：文字聊天；语音与打断；思考气泡与情绪分类；Live2D 自动情绪、手动动作/表情、口型、取消恢复与模型切换；游戏 program/advise/standby、暂停聊天及退出续聊；主动话题续接；手改人设和自动演化；删除后重启；性能与回滚验证。对应 design A01—A16。

合成演化数据保留在演练目录。正式环境需要等待独立经历时，将该场景登记为待验收，继续验证其他链路，不向用户记忆写入伪造经历。

交付：版本/数据位置/启动方式、当前模式与冻结范围、A01—A16 结果、可用回滚命令。出现影响原体验的问题，按 C05 演练回滚并保留切换后新数据。

**3. 管理台的页面与 API 合同**

下表是接线目标，实际端点沿用现有 API 与 C01 映射结果；已有核心方法优先复用。

| 页面 | 用户主要任务 | 必须取到的真实信息 |
|---|---|---|
| 概览 | 看最近发生了什么、处理待办 | 当前角色/数据源、最近经历、待审核变化、保存/采用状态 |
| 时间流/记忆 | 搜索、更正、忘记一段经历 | 原文或摘要、来源、时间、主体/场景、episode、删除回执 |
| 事实/反思与成长 | 查看为什么这样理解 | 原始依据、独立支持、适用范围、替代/撤回关系 |
| 人格卡 | 阅读、编辑、冻结、看历史差异 | 当前 revision、初始卡、段落来源、可演化范围、编辑冲突 |
| 演化 | 选择模式，审核或撤回变化 | 提案差异、依据、审核原因、预算/失败结果、接受后的 revision |
| 发布 | 查看新卡在哪里已生效 | 目标版本、普通/实时/游戏采用状态、待处理与失败重试 |
| 清理 | 明确范围地更正或删除 | 影响的记忆/派生物、pending/failed/completed、插件回执 |
| 设置 | 配置当前角色的演化方式 | 模式、范围、预算、连接状态；宿主资源配置链接到原入口 |

首屏优先近期内容、当前卡与待处理变化。数量统计服务于浏览；“记忆温度”等探索性图表须有真实定义与来源，演示数据明确标注。没有业务定义的指标可留在设计预览中。

“已保存”和“已生效”分别取持久提交与消费者回执。关闭演化、撤回一次修订、恢复初始卡、删除经历使用不同动作名称，并说明各自影响。

**4. 视觉建议：以「月白」为主的个人记忆工作室**

建议基于现有 `webui/designs/tsukishiro/` 月白方案继续：温暖纸白、墨色正文、克制朱红、细分隔线，少量宋体标题与清晰无衬线正文。角色头像、经历时间和来源关系提供陪伴感。此节是设计建议，由用户当前 WebUI 工作决定采用范围。

三套现有预览的取舍：月白适合长时间阅读记忆与改卡；星屑适合后续夜间主题，但应减弱满屏纹样与光晕；霓虹适合技术状态或可选主题。首版先把一个主主题和完整交互做好。

| 语义 | 建议起点 | 用途 |
|---|---|---|
| 页面底色 | `#F6F3ED` | 暖纸白，正文区保持平整 |
| 内容底色 | `#FFFDFA` | 编辑区、详情、浮层 |
| 主文字 | `#292621` | 正文、标题与关键状态 |
| 次文字 | `#71695E` | 时间、来源、说明 |
| 分隔线 | `#DED8CD` | 列表与段落层级 |
| 主强调 | `#A43A2B` | 主按钮、选中标记、少量角色点缀 |
| 已采用/有效 | `#37634B` | 配合文字标签的状态 |
| 待处理 | `#805514` | 待审核、等待消费者 |

具体落地建议：

- 月白预览的大标题和装饰留在欢迎页；日常概览压缩到一行问候与关键状态，让最近经历和待审变化进入首屏。
- 内容页用窄侧栏、可检索主列表、按需打开的右侧详情。人格卡主区保留连续可读的文本，来源与版本放侧栏；差异页可切换前后对照。
